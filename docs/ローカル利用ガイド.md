# ローカル利用ガイド（複数PC・Supabase 共用）

このアプリは **各 PC で起動する Web アプリ** です。**データベースはクラウドの Supabase 1 つ**を全 PC で共有します。  
**Vercel などのホスティングは使いません**（インターネットにアプリ本体を公開しない運用）。

```
[PC A] ──┐
[PC B] ──┼── npm run dev（ブラウザ）──► Supabase（PostgreSQL / Auth / Realtime）
[PC C] ──┘
```

---

## 他の PC に渡すとき（管理者向け）

### 渡すもの

| 方法 | 内容 |
|------|------|
| **おすすめ** | Git リポジトリの URL（clone）または ZIP |
| **必須（秘密）** | `.env.local`（Supabase の接続設定） |
| **含めない** | `node_modules`、`.next`（受け取り側で自動生成） |

ZIP にする場合の目安:

1. プロジェクトフォルダをコピー
2. `node_modules` と `.next` フォルダを削除してから圧縮
3. **別経路**（対面・社内共有など）で `.env.local` を渡す（メール本文に貼らない）

### 受け取った PC での初回セットアップ

1. [Node.js LTS](https://nodejs.org/) をインストール（未インストールの場合）
2. フォルダに `.env.local` を置く（`.env.local.example` を名前変更しただけでは動きません）
3. **`起動.bat`** をダブルクリック  
   - 初回は `npm install` が走ります（数分）
4. ブラウザが `http://127.0.0.1:3000` を開きます（開発モードではダッシュボードへ）

表示がおかしいときは **`キャッシュクリアして起動.bat`** を実行してください。

---

## `.env.local` の中身（3 項目）

Supabase ダッシュボード → **Settings → API** から取得します。**全 PC で同じ Supabase プロジェクトを指す**と、機器台帳・点検・依頼が共有されます。

```env
NEXT_PUBLIC_SUPABASE_URL=https://xxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJ...
SUPABASE_SERVICE_ROLE_KEY=eyJ...
```

| 変数 | 説明 |
|------|------|
| `NEXT_PUBLIC_SUPABASE_URL` | プロジェクト URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon（公開キー。RLS で保護） |
| `SUPABASE_SERVICE_ROLE_KEY` | service_role（**秘密**。Git・ZIP に載せない） |

## 起動のしかた（日常）

| ファイル | 用途 |
|----------|------|
| `起動.bat` | 通常起動 |
| `キャッシュクリアして起動.bat` | 画面が真っ白・古い表示のままのとき |

- **黒いコンソールを閉じるとアプリは停止**します（その PC だけ使えなくなります）
- 同時に **複数 PC から同じ Supabase** に接続して作業して問題ありません（Realtime で一覧が更新されます）

## ログインについて（`npm run dev` = 開発モード）

`起動.bat` は内部的に **`npm run dev`** を使います。

### A. ログイン画面を出して「一般用」で入る（おすすめ・本人の名前で操作）

1. 管理者 PC で **ユーザー管理** から「一般用」ユーザーを作成（PIN は **6桁**）
2. 渡す PC の `.env.local` に次を追加して **`起動.bat` を再起動**:
   ```env
   ALLOW_PIN_LOGIN_BYPASS=false
   ```
3. ブラウザで **「一般用」タブ** → 名前選択 → 6桁 PIN

管理者 PC は従来どおりログイン省略のままでも構いません（`.env.local` を PC ごとに分ける）。

### B. ログイン省略のまま「一般用」権限で使う

ログイン画面は出ませんが、**管理者以外の権限**で動かしたい PC 向けです。

1. 事前に Supabase に `role=staff` のユーザーがいること（ユーザー管理で作成）
2. その PC の `.env.local` に **どちらか一方**を追加:
   ```env
   # 登録が古い順で最初の一般用ユーザー
   DEV_AUTO_LOGIN_ROLE=staff
   ```
   ```env
   # 特定の人を固定（ユーザー管理や Supabase の profiles.id）
   DEV_AUTO_LOGIN_USER_ID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
   ```
3. `起動.bat` を再起動

未指定の場合は従来どおり **管理者** で自動ログインします。

### C. 管理者 PC（既定）

`DEV_AUTO_LOGIN_*` も `ALLOW_PIN_LOGIN_BYPASS=false` も書かない → **管理者** でログイン省略。

---

本番ビルド（`npm run build` → `npm start`）は PIN 必須です。病院内では **`起動.bat` 運用を推奨**します。

## 新規病院・DB をゼロから作る場合

1. [supabase.com](https://supabase.com) でプロジェクト作成
2. `起動.bat` でアプリ起動
3. `http://127.0.0.1:3000/setup` のウィザード（未設定時）または README の手順でスキーマ・管理者を作成

既に運用中の Supabase がある場合は、**スキーマは触らず** `.env.local` だけ各 PC にコピーすれば足ります。

## 同じ LAN の別 PC から「この PC で起動したサーバー」だけ見る

通常は **各 PC で自分用に `起動.bat`** する想定です。  
1 台の PC だけをサーバーにして他からブラウザで見る場合:

```bash
npm run dev:lan
```

ファイアウォールでポート 3000 を許可し、他 PC のブラウザから `http://<サーバーPCのIP>:3000` を開きます。  
**Supabase のデータは変わりません**（表示だけが 1 台集中）。

---

## トラブルシュート

| 症状 | 対処 |
|------|------|
| `.env.local がありません` | 管理者 PC から同ファイルをコピー |
| ずっと「読み込み中」 | `キャッシュクリアして起動.bat` → ハードリロード（Ctrl+Shift+R） |
| Node.js がない | [nodejs.org](https://nodejs.org/) LTS をインストール |
| PIN / ユーザ一覧が空 | Supabase に `profiles` と `profile_auth_secrets` があるか確認 |
| 別アプリが表示される | URL が `127.0.0.1:3000` か確認（ポート 3010 等ではない） |
